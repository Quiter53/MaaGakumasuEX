# 本地完整包的手动转存

本机可以访问 GitHub API、但无法连接资产上传域名时，可使用 `Upload verified local package` 工作流转存已经在本机构建并校验过的公开安装包。工作流只接受手动触发，不监听推送、标签或定时事件，也不负责公开 Release 或切换 Latest。

维护者将公开 ZIP 和校验文件按块写入同仓库的 Git blob API，再写入包含版本、构建提交、Release ID、逐块大小及 SHA-256 的清单 blob。无需将二进制块提交到分支或源码树。清单格式见 `tools/upload_verified_package.py`。

在对应构建提交的 main 或 pre 上手动触发，输入清单的 Git blob SHA。工作流检查构建提交与版本，重建本地原始文件，核对逐块和完整 SHA-256，再上传带构建后缀的暂存资产并核对 GitHub 返回的摘要。维护者随后检查远端结果，再将资产改为正式文件名并设置发布渠道。

只允许公开发行包及其校验文件使用此路径；个人配置、日志、账号信息和截图不属于上传输入。GitHub 任务使用仓库自身的临时令牌，无需保存新的访问密钥。
