# 回忆生成、奖励除去与多选设置修复

## 日志原因

2026-11-02 21:55:45，原生 OCR 在 `[320,954,78,45]` 识别到“生成”，置信度 0.999976。21:55:46 点击提交成功，截图中的游戏仍停在生成页。原节点后续列表缺少自身，无法重新处理仍显示的生成按钮，转而反复走左上角 Click_1，21:58:50 被三分钟循环保护停止。原“回忆已生成”日志实际在识别成功时就输出，早于游戏确认。

21:25:18 确认奖励卡除去后，游戏进入除去结果动画。旧处理仅等待奖励卡完整出现，21:25:25 放弃局部恢复。21:25:26 的 OCR 已出现“トレンドリーダーを除去しました”，外层流程随后点击左上角，21:25:29 才重新进入奖励识别。除去次数耗尽时，次数标签消失也会使仅依赖数字下降的确认保持待定。

出牌场景识别函数会无条件调用 Click_1，演出识别的 tap 参数也会使失败的识别产生点击。这些操作发生在候选页面识别过程中，可能使同一轮识别使用的截图与游戏当前页面不一致。

## 修改

- 生成节点精确匹配“生成”并继续检查该按钮，排除“再生成”，点击后等待 300ms 再判断下一页。每次点击基于新识别结果，日志改为“点击生成回忆”。
- 奖励除去恢复覆盖结果动画。只在已发起除去的恢复路径识别底部除去成功文案，确认对应的一次消耗后推进结果页，重新等待稳定奖励卡。结果文案可确认最后一次消耗，次数标签缺失不会直接被当成零。
- 场景识别函数只返回识别结果。现有演出跳过动作和流水线末尾的推进动作继续负责页面推进。
- 通用多选项移除滚动文字和首次布局统一撑宽逻辑，使用自然宽度、勾选标记、玻璃悬停反馈及长文字换行。道具图片卡片继续使用专门布局，手动接管保存仍为多选集合。

## 实际验证

- 使用用户生成页截图与 MaaFramework 5.13 原生 OCR，在虚拟控制器中模拟前两次点击未生效。旧后续列表点击一次后超时，修复后第三次点击进入模拟下一页。运行脚本为 `tests/run_generation_recovery.py`。
- 除去结果延迟出现、最后一次次数标签消失、无待确认除去时不点击结果、弹窗吞点击、断线及停止等针对性回归通过。
- Lab 当前源码回归通过 1264 项测试、1322 项子测试。
- 原生培育结算的 1、2、6 次循环检查通过。
- Headless 任务选项回归通过 1002 项，覆盖手动接管独立多选/取消及 900px、420px 面板截图。
- 资源检查与 Python 编译通过。Windows 安装包及实际窗口检查由当前提交的 CI 执行。

原生回放使用虚拟控制器，完整实机培育留待测试。日志还出现热绿茶使用后等待出牌超时，随后约一秒重新识别到战斗页。现有日志不足以区分动画未结束与出牌就绪识别遗漏，需结合当时画面进一步定位。
