# EX 原生界面与构建入口

完整客户端源码位于 `native-ui/`，规则、名单、饮料页面直接在该目录维护。无需向外部客户端复制 UI 补丁。

在仓库根目录执行：

```powershell
dotnet build native-ui/MFAAvalonia/MFAAvalonia.csproj -c Release -r win-x64
python tools/build_ex_release.py --runtime "D:\EX-runtime" --ui-core "native-ui/MFAAvalonia/bin/Release/net10.0/win-x64/MFAAvalonia.Core.dll" --output "D:\EX-new-portable"
```

输出目录和对应 ZIP 必须尚不存在。依赖基线应为已验证的 EX 运行包；保持 MaaFramework 5.13.0、原卡牌检测模型和 DMM PrintWindow。构建工具生成公开默认配置，不应将个人配置复制到发布包。

`tests/CardRulesUi`、`tests/CardListUi`、`tests/DrinkUi` 均引用 `native-ui/MFAAvalonia/MFAAvalonia.csproj`。UI 测试使用独立目录，不覆盖个人设置。规则测试还可导出 `native-policy-vectors.json`，供 Python 规则等价性检查使用。

公共卡牌库为 `assets/config/card_library.json`。卡牌名单、出牌规则与饮料策略分别存放在运行目录的 `config/card_lists.json`、`config/card_rules.json`、`config/drink_policy.json`。保留已有预设、语言、布局和配置迁移功能。

新增卡牌使用 `tools/import_card_art.py`，更新卡牌目录、选卡图片与正式识别共用的 `card_fingerprints.npz`。卡牌框检测、战斗手牌识别、普通奖励识别和整页方形卡图识别仍分别使用各自现有实现。

界面保持原生 Avalonia；HTML 只作设计参考。已移除的临时出牌策略、外部 UI 覆盖脚本、旧版打包脚本和 Mirror 酱发布工作流不应重新接入正式构建。
