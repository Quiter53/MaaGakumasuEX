# 逻辑审查与冲分任务设计

日期：2026-09-06。

## 审查结论

静态检查覆盖 agent 下 18 个 Python 文件和 assets 下 34 个 JSON 文件；重点逐段检查培育入口、续培、奖励选择、除去与刷新、出牌识别和商店动作。Python 语法、JSON 解析、自定义动作与识别注册引用检查通过，base、zh_CN、DMM 资源加载通过。静态检查不能替代所有玩法的实机验证。

培育主文件原有 3489 行，包含事件规划、出牌、奖励、饮料、商店和异常恢复。主要维护负担是多个子系统共享状态，以及识别、点击和业务成功判定混在一起；文件大本身并不能证明功能错误。

## 已修复的奖励计数问题

历史日志 `debug/custom/2026-09-02.log` 记录过除去 14 次、刷新 31 次。任务入口 Produce 只调用一次名单加载与状态重置，连续培育却通过 ProduceLoop 开始下一局，导致累计数跨局沿用。

旧逻辑还存在以下问题：

- 除去确认按钮点击后立即加一，没有等待消耗成立。
- 刷新把卡图颜色网格或识别结果变化当作成功；动画、检测框抖动和识别结果变化都可能触发。
- 单次 OCR 可覆盖剩余次数并清除耗尽状态。
- 活动奖励页没有除去、刷新控件时，仍可能使用上一页缓存的预算点击固定位置。

新的 `reward_counts.py` 管理每种操作的剩余预算、已确认消耗和暂停状态。两帧高置信度 OCR 必须一致；只接受数字或明确的次数文本，不拼接任意文本中的数字。当前页也必须有与预算一致的次数读数才能尝试操作。

只有操作前后剩余数准确减少一，才累计一次；同一回报重复提交不重复记账。已知预算在本局只能减少，单纯 OCR 数字增大不能补充预算。预算未知、回报不一致或控件不存在时，继续按卡牌策略选择，不等待次数识别。

状态重置位于新培育的 ProduceMainPage，续培与普通任务重新开始不主动清零。整个程序退出后，下一次从当前画面重新建立剩余预算；“确认消耗”是本进程本局已核实的操作数，不假称知道退出前的历史消耗。

本实现不写死某个玩法的总次数。若玩法通过明确事件额外赠送次数，需要单独识别赠送事件并更新预算；当前不将未经证明的数字上涨解释为赠送。

奖励等待阶段新增停止与异常弹窗检查，异常时交回恢复流程，避免继续点击奖励兜底坐标。

## 卡牌识别的精度边界

当前识别链是 YOLO 定位、边框颜色稀有度、固定区域再动图标、32×32 卡图相关性匹配和部分 OCR 卡名兜底，并非统一的卡牌分类模型。

定位错误会让颜色、图标和卡名同时出错。手牌遮挡、数字覆盖、发光与灰态、动画和事件标签都会改变裁剪内容。奖励与商店还会用视觉匹配的卡牌元数据覆盖颜色结论；名称误匹配会进一步影响稀有度、再动和黑白名单。固定区域图标仍依赖正确卡框，不能因为图标相对位置固定就保证百分百。

真实运行不能承诺识别每张卡都百分百正确。有限且固定的标注样本可以做到全部通过，但不能据此证明未见过的卡图或画面也全部正确。现有网站素材标签、历史日志和少量回归截图不能计算可信的全流程准确率，尤其不能把程序自己输出的识别结果当作真值。

提高精度的顺序：先为历史失败画面人工标注卡框、卡名、稀有度、再动与可点击状态；按截图场次隔离训练和测试；修正卡框与事件标签裁剪；统一多来源识别冲突处理；最后针对剩余混淆样本调整模型。分别报告检出率、各字段准确率、未知率、最终选牌正确率以及点击成功率。本次未修改模型参数，也没有宣称达到新的准确率。

## 其他维护与策略问题

- v1.4.8 已将奖励稳定判断改为卡框位置与图像一致性，名称识别问题不再拖成等待超时。奖励与商店的卡图身份若与高置信度边框稀有度冲突，则舍弃该身份匹配。
- 除去确认仍使用橙色区域比例作为弹窗证据；本次消耗计数已不依赖该证据，但按钮识别仍适合改成明确弹窗与按钮定位。
- 商店购买后重新进入、重新扫描的处理分散在多个方法；只有明确购买成功才应更新本地商品与积分状态。
- 现有出牌按再动和稀有度排序，出牌开始会循环使用识别到的饮料；这不是以最终得分为目标的规划策略。
- 一些选项仍包含随机兜底。无法读取完整状态时有继续运行的价值，但对可复现的冲分策略不合适。

后续按奖励、商店、战斗、异常恢复拆分模块，每个模块统一输出“观察、计划、执行、验证”的结果。应随相关功能维护逐块迁移，避免一次重写全部培育流程。

## 独立冲高分任务

建议新增与“开始培育”并列的“冲高分 AI”任务，独立参数和运行状态，复用截图、识别、点击及恢复能力。第一版限定用户常用的筱泽广和一种明确玩法，先完成试镜战斗优化，再扩展到完整培育路线。

卡牌识别应优先确定卡牌 ID，再查卡牌效果。现有卡牌目录主要只有名称、稀有度与再动标记，尚不足以模拟得分；需补充消耗、增益、触发条件、抽牌、额外行动、持续回合以及强化变化。

每次决策读取剩余回合、行动次数、体力、手牌、状态层数、当前得分、饮料与已知牌堆信息。在规则模拟器中比较多种出牌与饮料顺序，计算预期最终得分，再执行一个动作并验证状态变化。未知抽牌按概率分支估计，不假设能知道未公开牌序。

再动牌并非无条件最优首选：某些增益在先会提高后续额外行动的价值。高稀有度也不能代替当前效果收益。评分器需要同时考虑即时得分、后续收益、体力可持续性与失败风险。

先运行只记录建议的模式，比较现有策略和规划策略；通过固定状态回放验证效果规则与决策，再进入自动操作。验收看相近条件下的平均最终得分、成功率、耗时和异常率，不以单次最高分或短样本胜率作结论。

规则数据与有限深度搜索可以在本地实现，第一版不需要引入大型语言模型或大体积模型运行环境。
