# EX 使用指南

## 启动与任务

下载 Windows x64 便携包 `MaaGakumasuEX-版本号-win-x64-portable.zip`，解压到独立目录，运行 `MaaGakumasu.exe`。运行包自带 Python 环境，发布说明附有 SHA-256 校验值。GitHub 页面上的 `Source code` 用于获取源码。[下载正式版](https://github.com/Quiter53/MaaGakumasuEX/releases/latest)

首次启动后，选择控制器和游戏资源并连接游戏，再检查任务中的培育难度、偶像、培育次数、体力药与道具选项。模拟器推荐使用 MuMu 12，竖屏画面以 `720 × 1280`、`240 DPI` 为配置参考。DMM 使用 PrintWindow 截图，助手与游戏应使用相同权限运行。培育前可在游戏设置中开启跳过对话和常见弹窗的选项。

日常任务包括活动费、邮箱与任务奖励、每周免费礼包、工作、竞赛、社团请求和商店兑换。偶像之路提供自动编队、战斗与失败重试。培育任务包含初 `REGULAR / PRO / MASTER`、NIA `PRO / MASTER`，以及 HIF 选拔和本战。

继续中断的培育时，先确认游戏场景和任务配置，再勾选“跳过准备阶段”。开始培育前，分别检查出牌规则与卡牌名单的当前预设，以及饮料设置。

“出牌后额外等待”从下一手牌稳定后计时，默认 1.5 秒，可设为 0～5 秒。设为 0 后，出牌仍会等待动画结束与手牌稳定。

## 出牌规则

### 设置与保存

“出牌规则”提供好调、集中、干劲、好印象、强气、全力六种职业预设，也可新建预设，通过“管理预设”整理自建预设。每个预设分别保存规则和预览手牌。开始培育前选好对应预设，修改后点击“保存规则”应用。

每张卡可设置允许使用的剩余回合、排序档位和优先级曲线。普通与强化版本共用规则，卡名使用游戏内原名。选卡窗口支持搜索与分类筛选。

例如，可将 `届いて！` 的使用范围设为剩余 1～2 回合，将 `せのびの魔法` 设为剩余 1～7 回合。按自己的卡组调整范围，再用页面下方的手牌预览检查效果。

曲线支持折线和阶梯两种模式。可以拖动节点，也可以精确输入“剩余回合 → 优先级”。分数范围为 `0～100`，未配置卡牌的默认分数为 `50`。手牌预览最多放入五张卡，调整剩余回合即可查看排序。“添加手牌”提供当前预设规则卡的快捷入口。

### 排序与生效范围

出牌先检查允许使用的回合，再依次比较再动、排序档位、曲线分数和手牌位置。同分时按手牌槽位顺序处理。

| 设置 | 作用 |
| --- | --- |
| 使用回合 | 决定该牌在当前剩余回合是否可用 |
| 自定义再动 | 将该牌纳入助手的再动优先级，默认关闭 |
| 排序档位 | 默认采用卡牌稀有度，R、SR 可提高档位，SSR 可降至 R 或 SR |
| 优先级曲线 | 再动状态与档位相同时，分数较高的牌先出 |

回合限制和曲线用于战斗出牌。R、SR 的升档还用于奖励选牌、奖励刷新停止条件、换入换出、商店买牌排序、删牌和常规回忆比较。升档后的牌按新档位获得保留优先级，显式黑名单和替换名单仍按各自用途生效。商店购买范围由白名单决定。

SSR 降档用于战斗排序。开启并保存“自定义再动”后，其优先级同时用于战斗、奖励和 HIF 换入、咨询购买排序及常规回忆比较。停用规则或切换预设后，策略读取当前有效配置。

### 最多保留一张

逐卡规则中的“最多保留一张”默认关闭。启用后，准备获取该牌时会检查当前牌组。已经持有时优先选择其他非黑名单牌，其他候选均被排除时允许重复。后续咨询删牌和 HIF 换出会优先清理多余副本，并保护最后一张。

HIF 换牌支持同名交换。确认已经持有限一目标牌后，可以换入该牌，并将本次换出限定为同名旧牌。同名旧牌可选且身份确认后完成交换，持有数量保持一致。

### 国民与初星黑醋

在 `国民的アイドル` 的规则中，通过“选择要生效的牌”指定一张配合牌，或用“清除”取消设置，修改后保存规则。

初星黑醋跟随这项配合规则。准备打出国民或配合牌时，如果另一张缺席，就尝试喝黑醋取牌。两张都在手中时保留黑醋，缺少黑醋时照常出牌。取牌后重新读取手牌并按当前规则排序，国民成功打出后的下一张牌跳过黑醋检查。

两张牌的可用回合和优先级可在规则页分别调整。页面会提示回合范围或优先级冲突，便于配合手牌预览检查。[配合规则说明](../fixes/national-vinegar-20261020.md)

## 卡牌名单与饮料

### 卡牌名单

“卡牌黑白名单”按预设保存三种名单。

| 名单 | 用途 |
| --- | --- |
| 黑名单 | 获取卡牌时规避目标 |
| 白名单 | 优先获取，并作为商店买牌范围 |
| 替换名单 | 变卡时优先换出目标 |

黑白名单互斥，替换名单独立。从卡牌库拖入名单后，当前预设的修改立即保存。名单预设与出牌规则预设分别管理，切换职业时分别选好。

### 饮料

饮料页可勾选目标饮料，并为普通饮料选择开局使用、指定卡牌出牌前使用，或最后若干回合内使用。获取、满包处理和战斗使用会读取这些设置，最后一回合会兜底使用普通饮料。初星黑醋按国民配合规则处理。

使用前会核对当前饮料与弹窗状态。目标饮料设置还会影响商店购买和满包时的腾位选择。

## HIF 与自动自定义

### HIF 设置

在“培育难度”中选择 HIF，再选择选拔或本战。本战可配置上课属性、第三周行动、外出选项、幕间回血目标和试镜手动接管。第三周默认选择支给，选择外出后可指定第一、第二或第三选项。

“普通商店删牌”用于 HIF 普通商店，默认关闭以节省积分。商店、删换牌和战斗会结合当前卡牌名单、出牌规则及饮料策略执行。

### 设置自定义目标

在“跳过选择偶像”下开启“启用自动自定义”，进入“自定义卡牌设置”，添加目标卡并调整优先顺序。该开关默认关闭。

选项 1、2、3 对应游戏菜单从左到右的选项。次数表示最终希望达到的次数，包含已有自定义。例如 `[2,0,1]` 表示第一项最终两次、第三项最终一次。窗口根据具体卡牌显示可用选项和次数上限。

执行对象为已持有且已强化的目标卡，准备卡组时先完成目标卡的获取与强化。助手按目标顺序补足自定义次数，同一张卡按选项 1→2→3 处理，已有其他选项也计入游戏总上限。

### 执行顺序

HIF 轮间商店先回血，再处理本批最多两张卡的自定义，随后购买当前目标饮料。存在已确认的未完成目标，且余额足以支付刷新和下一次自定义时，刷新后继续下一批。优先目标买不起时结束本轮自定义，随后继续商店流程。

同一张实体卡首次自定义占一个名额，继续处理这张卡的其他选项沿用该名额。普通特别指导处理当前节点允许的两张卡，完成后返回培育流程。

每笔操作前会核对卡名、剩余次数、价格、余额与选中项，提交后确认结果再继续。积分读取不清时暂缓本批，后续进入可用页面时重新检查。[自动自定义说明](../fixes/auto-customize-20261017.md)

## 回忆收集

在“培育模式”中选择“刷取卡牌回忆”或“刷取卡组”，再打开目标选择界面。两种模式都可设置强化状态与绿豆数量下限，绿豆为 0 时接受任意数量。

### 刷取卡牌回忆

添加所需的回忆获得卡，可同时配置多个目标，最多 64 项。每个目标按卡名、强化状态和绿豆下限匹配。候选比较还会参考钻石词条，优先保留符合目标的钻石回忆。

目标随培育轮次逐项收集。确认保存回忆并返回主页后，才记录本轮完成的目标。相同一组目标的进度保存在 `config/memory_farming_progress.json`，重新启动任务时读取未完成进度。全部目标收齐后结束循环，再次主动启动这组已完成目标时开始新一批。

### 刷取卡组

卡组模式检查同一份回忆的 Stage 卡组。第 1 格限定角色卡，第 2 格限定支援卡，第 3～6 格用于普通卡，留空的格子接受任意卡牌。

同一份回忆满足全部已选目标才算达标。普通卡按无序组合匹配，重复选择同名卡时，需要相应数量的合格实体副本。完成结算后结束循环，其余轮次继续寻找符合整组条件的回忆。[卡组条件说明](../fixes/memory-deck-audit-20261019.md)

### 再生成回忆

收集模式在回忆未达标时尝试使用再生成票，再比较候选。常规培育提供默认关闭的“再生成回忆”，开启后每轮最多使用一次再生成票，再依次比较钻石词条、绿豆数量、再动与卡牌档位，同分时保留原回忆。常规培育仍按设置的培育次数运行。

## 配置与更新

### 配置文件

个人配置主要位于运行目录的 `config/`，界面设置同时使用 `appsettings.json`。

| 文件或目录 | 内容 |
| --- | --- |
| `config/card_rules.json` | 出牌规则、当前预设与预览手牌 |
| `config/card_lists.json` | 黑白名单、替换名单与名单预设 |
| `config/drink_policy.json` | 目标饮料与使用时机 |
| `config/memory_farming_progress.json` | 卡牌回忆的跨轮收集进度 |
| `config/instances/` | 任务实例及连接等实例配置 |
| `appsettings.json` | 客户端设置 |

“控制器预设配置”位于“设置 → 连接设置”。DMM 点击延迟可在这里调整，执行任务时自动应用。

### 更新

“设置 → 版本更新”提供“检查更新”“更新完整包”和“重新下载完整包”，也可启用启动检查与自动更新。“更新渠道”默认选择稳定版，主动选择测试版后才会检查预发布。

EX 从自己的 GitHub Releases 获取完整包，界面、策略与资源随包更新。[发布页面](https://github.com/Quiter53/MaaGakumasuEX/releases)

升级前停止任务、退出助手，并备份 `config/` 与 `appsettings.json`。手动升级可解压到新目录，再复制个人配置。其中 `config/card_library.json` 是随包更新的公共卡牌库，应使用新包中的文件。内置更新会保留已有个人配置，并更新公共卡牌库。

检查更新出现 `403 / rate limit exceeded` 时，可稍后重试，或从发布页面手动下载完整包。

## 本地构建

需要 Git、Python 3.12+、.NET SDK 10，以及一份已验证的 EX Windows x64 运行包作为依赖基线。原生界面源码位于 `native-ui/`，Python 扩展位于 `agent/`，任务、图片和公共配置位于 `assets/`。

在仓库根目录构建原生界面。

```powershell
dotnet build native-ui/MFAAvalonia/MFAAvalonia.csproj -c Release -r win-x64 -p:CopyLocalLockFileAssemblies=true
```

将依赖基线包解压到 `D:\EX-runtime`，执行下面的命令生成运行目录、ZIP 和校验文件。选择一个尚未使用的输出目录，其同名 ZIP 也应尚未存在。

```powershell
$version = (Get-Content assets/interface.json -Raw | ConvertFrom-Json).version
python tools/build_ex_release.py `
  --runtime "D:\EX-runtime" `
  --ui-core "native-ui/MFAAvalonia/bin/Release/net10.0/win-x64/MFAAvalonia.Core.dll" `
  --output "dist/MaaGakumasuEX-$version-win-x64-portable"
```

打包工具装入当前源码对应的界面、脚本与资源，生成公共默认配置，校验两端 MaaFramework DLL，并检查 ZIP 的 CRC 与逐文件哈希。源码构建和依赖基线使用 MaaFramework **5.13.0**。[源码组织](../development/source-layout.md) · [开发相关](开发相关.md) · [发布渠道](../releases/channels.md)

## 日志与反馈

“调试诊断”控制识别诊断日志与异常截图，默认关闭。排查漏认、误点或卡住时，可临时开启并保存相关时段的日志与完整游戏截图。

程序会监测任务日志。连续 5 分钟没有日志，或同一条、一组日志持续循环 3 分钟且至少重复 30 条时，会停止任务并保留现场。手动接管和等待确认期间暂停计时。启用外部通知后，自动结束的任务会推送结果、任务名称、原因与耗时。

反馈时附上 EX 版本、Windows 与模拟器或 DMM 环境、游戏语言、分辨率、任务配置、发生时间，以及相应日志和截图。[提交问题](https://github.com/Quiter53/MaaGakumasuEX/issues)

日志通常位于 `logs/` 和 `debug/`，排查识别问题优先查看 `debug/maa.log`。分享前隐去账号信息、连接地址和其他个人内容。[提问与反馈指南](提问与反馈指南.md)
