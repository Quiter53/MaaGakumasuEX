# 饮料策略

侧栏新增“饮料策略”，复用现有客户端风格、卡图及分类。28 种饮料以资源 ID 保存，中文名用于展示，日文名用于核实。目标状态与使用时机互不影响；默认六种目标、开局使用。每种只选一种时机：开局、指定牌前、倒数 N 回合。最后一回合兜底使用剩余饮料。

配置文件为 `config/drink_policy.json`，编辑即时原子保存，不修改卡牌黑白名单。战斗开始读取配置快照；修改在下一次战斗动作生效。非法文件不能静默回退到全部开局使用。

中途启动任务时，“开局使用”沿用原有行为，指本次接管的首次出牌阶段；不会推测已经过去的回合或倒推已使用的饮料。

验收需分别检查：配置往返及筛选、原有卡牌策略回归、小区域识别与缓存失效、实际游戏中的回合语义及喝药后的手牌变化。离线测试不能代替完整实机培育。

## 识别与速度

保留原手牌模型和再动／稀有度优先级。先选牌，在原有第一次点击之后仅核实待出牌名称；只认本地卡库中的完整名称，支持唯一对应的浊音及大小假名归一化，不用前缀猜牌。第一次 OCR 失败时补读底部单行，不遍历点开整手牌。

左上角剩余回合数字需两次一致才生效；区域变化立即废弃旧读数，允许加回合卡令数字增大。区域不变时使用内存缓存。只有已确认的战斗页才调用此读取器。

全为默认开局规则时不需要逐瓶读取名字。存在延迟规则时，每个新出现／变化的持有图标读取一次详情，结果随图标缓存；不明身份不提前喝。喝药后确认持有数减少，再重扫手牌；指定卡牌前喝药还会锁定原定牌名，不能因抽牌改变优先级而误出另一张牌。新手牌中找不到原定牌时保留现场，不盲点旧坐标。

最后一回合兜底一旦启动，将连续处理当前剩余饮料；即使期间饮料增加回合，也完成这次兜底。网络弹窗交回原恢复流程。确认失败有界停止，不把未知当作喝药成功。
