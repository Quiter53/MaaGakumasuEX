# 奖励弹层恢复与补丁合并

本次将桌面覆盖补丁的页面恢复逻辑合入源码，并补回原版的参数兼容及剩余次数核实。黑白名单、再动与稀有度优先级、饮料选择和营业属性策略保持现有配置。

## 恢复流程

正常奖励页先等待稳定，再执行现有选牌策略。卡牌识别前检查除去确认弹窗、卡牌详情页和除去选卡模式，避免把弹层中的卡牌缩略图当作奖励牌。

一次除去先记录剩余次数，再点击除去按钮。确认弹窗必须同时满足固定区域的橙色按钮和除去文字条件；最多点击确认三次，每次使用新画面检查。随后关闭残留详情页或选卡模式，重新取得稳定奖励牌。

正常确认和恢复补点共用同一个次数核实出口。只有两帧一致的剩余次数从 N 变为 N−1，才增加一次确认消耗。断线或读数未知时保存待核实操作，后续奖励页先核实，禁止直接开始第二次操作。已知读数没有减少时暂停该预算，按原有非黑名单选择规则继续。

没有待核实除去意图的确认弹窗会被取消。恢复超出限制时交回专用节点，不在弹层内按第一张牌的坐标点击。关闭节点连接回任务配置的培育入口，初、NIA、HIF 主循环均可从残留弹层继续；关闭后已离开奖励页时也能继续当前难度。恢复节点点击后延时 600 毫秒，不等待整屏冻结，避免人物动画使冻结检查达到 20 秒超时。

## 商店与参数

商店评论气泡使用固定区域的白色面板特征，并要求商店头部识别命中后才点击。最多点击三次，点击后重新检查；通信错误、停止或页面变化会结束恢复。普通商品页没有气泡时不额外执行头部识别。饮料满栏检查通过明确的商品类型启用，兼容“最低价饮料”等日志名称。

选项与挑战统一解析可选参数，支持 JSON 字符串和字典。空值、非法 JSON 及非字典数据使用默认配置；只有布尔值 true 可以启用连续失败保底，字符串 "false" 不启用。

65 项单元测试通过，包含吞掉确认点击、连续弹层、确认重试耗尽、中断后的单次记账、四卡奖励、过期画面、缩放坐标、商店气泡、饮料满栏和参数兼容。部署后的 MaaFramework 5.13.0 成功加载 base、zh_CN、DMM 三层资源及新增恢复节点，恢复路线与延时参数检查通过。实际 Agent 与客户端握手成功，注册 23 个动作、10 个识别，并正常退出；该检查不连接游戏设备。

本机没有安装 maa-tools、pytest、ruff，本次使用现有 unittest、Python 编译检查及实际 MaaFramework 资源加载和握手检查完成验证。
