# HIF 换卡目标页三牌与四牌布局

## 原因

运行日志 `log-20261011.log` 的 02:01:08 记录目标框 `[159,833,124,129]`。`read_hif_change` 原先仅检查三个固定区域内的青色背景，直接返回三牌坐标。活动四牌布局也覆盖这些区域，导致错误裁图、误认牌名与点击落在卡牌边缘。

## 实现

换卡目标页通过原 `ProduceRecognitionCards` 检测实际框，使用共享 `reward_card_row` 校验完整三牌或四牌行，按横向位置排序并裁去活动徽标。仍须 OCR 命中换卡目标页的专用提示；缺失任意一张不返回固定槽位。选卡优先级和后续换出牌规则不变。

- 用户提供的 `codex-clipboard-37395a3c-8b6f-416a-80b8-57c3070fa7fc.png`，游戏客户区 `(771,85,1491,1365)`，720×1280；本地 MaaFramework 离线回放，控制器禁止输入。
- 原模型四个真实框置信度：0.956401、0.951308、0.953000、0.941305；上方占位图的低置信度框被行布局校验排除。
- 输出卡框：`[89,837,125,125]`、`[229,839,123,123]`、`[367,839,124,124]`、`[507,840,123,123]`。第一张中心为 `(151,899)`，不是原三牌位 `(221,897)`。
- 四个名称：びしっとキメ顔、ラブリーウインク、ファンシーチャーム、スポットライト，与截图一致。
- 326 项 Python 回归通过，含三牌、四牌中心、缺失事件卡拒绝猜测、模拟点击后下一步确认；`compileall` 通过。沙箱内临时目录清理失败的测试已在沙箱外重跑通过。
- UI 两处指定文字已删除；原生 UI 构建和隔离配置测试通过，检查了更新后的渲染图。用户配置不被测试修改。

离线回放验证识别结果，模拟控制器验证点击顺序；尚未验证当前实机换卡操作或完整培育。
