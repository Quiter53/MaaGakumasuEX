# 识别结果未知时的流程处理

回忆结算不能因为短暂漏读就交给通用“下一步”，也不能通过两帧空 OCR 判断保存成功。自定义同样不能把未读到积分当成余额不足。

本次修改：

- 回忆结果页、候选比较页分别局部读取页签、底部按钮及候选序号，复用同帧标题。全屏 OCR 继续提供正文。
- 已接管的回忆在短暂未知页、控件动画期间保留处理状态；每次回调仍限制为 30 秒。确认目的页后交回对应流程，断网仍交给原恢复节点。持续未知且无操作证据时不盲点，由现有无进展检测处理。
- 已检查回忆而漏读再生成按钮时，最多观察五帧。仍未确认则明确告知本轮未使用票，保留当前候选继续，不声称票不足。原有用票上限、候选排名、未知卡保留策略不变。
- 保存标记改为确认结算目的页；经过关注/剧情弹窗的情况在实际回到主页时提交进度。
- 丢饮料恢复复用同帧已确认标题，取消按钮仍须独立识别。后续新截图重新识别弹窗，不沿用旧帧标题。
- 商店自定义积分未知时追加三次新截图读取；仍未知则明确暂缓本批、继续商店流程，保留后续重试资格。真实积分不足仍按原逻辑结束自定义，不改变刷新和买饮料顺序。

验证：缺失页签、底部按钮、空帧、断网、再生成入口短暂/持续缺失、积分恢复、取消按钮缺失等回归用例；现有回忆、商店和自定义全流程模拟继续运行。实际 MaaFramework 5.13.0 使用三张旧现场截图，各按 1279/1280/1281 高度回放，九组页面类型、按钮和候选序号检查通过。没有新实机完整培育记录。

未更换 OCR 模型、未降低识别阈值、未更改卡牌或饮料策略。只部署 pre，保留 latest 和个人配置。
