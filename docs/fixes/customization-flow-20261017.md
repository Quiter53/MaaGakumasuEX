# 自定义重复回顶与菜单预扫描

03:12 的运行已加载 `v2.0.3-cultivation-scroll-20261017`。本轮没有再次出现“牌库翻页重叠未确认”：29 秒进入菜单，30 秒返回列表，41 秒返回商店，42 秒再次进入自定义；43 秒客户端发出停止指令，随后旧代码把停止写成“自定义观察已结束”。现场并未执行购买，不能把这条停止记录认作超时或识别失败。

问题是交互流程绕路：每次扫描先用两次静止拖动回顶，再完整收集所有目标菜单的进度，退回商店后逐张回顶重找。当前只配置「輝くキミへ」也走这套流程；上次仅更换手势，没有消除这些往返。

## 改动

- 自定义列表复用共用滚动条提取器，但采用此页面的外侧区域与亮度配置：x=695..709，亮色滑块与下方暗灰轨道分开识别。用户截图的滑块为 y=565..793，已证明在顶部，直接扫描；确认到底也不再用额外拖动探测。未知位置仍保留有界复核，已识别在中部的滚动条会否决“滑不动就是顶部”的判断。
- 两次额度均可用时，按用户顺序寻找第一个未完成目标，在已经打开的菜单直接自定义。最高优先目标积分不足就停止本轮，不消费低优先目标。定向查找中，卡图未识别却点开其他规则卡时，不会把它当成当前目标。
- 第一笔完成后核对扣款回执和额度减少，再规划最后一次额度。最后额度前保留完整后续计划，使刷新仍须建立在已确认存在未完成目标、且积分足够的条件上；初次只剩一次额度时也沿用完整规划。并非取消所有扫描。
- 日志明确显示“开始自定义：卡名，选项 N”。手动停止不记识别失败、不把本店标成失败封锁，不新增任何后续点击。真正的观察超时单独记录。
