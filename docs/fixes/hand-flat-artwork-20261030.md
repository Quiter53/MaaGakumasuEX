# 纯色卡面与角标共同造成的错误接受

Lab 固定源码 `b06e998e76a35e8c5b801bba8d15f652aee34954` 的两个合成实验出现 14/600 和 6/300 次负样本错误接受。本次在 Linux / Python 3.12.14 上重现了全部 20 例，基线与原角标实现均接受，全部预测为「夢はまだ続く」。20 例均为纯色替换卡面，角标仍保留；随机噪声子集未出现错误接受。相似度约为 0.4011–0.4639，候选分差约为 0.0949–0.1818，均能通过普通门控；18 例未检出角标边框。

原识别器先按普通分数确认，拒识后才尝试角标恢复。纯色区域没有卡面结构，保留下来的角标却能主导匹配，因此仅调整角标恢复分支无法覆盖这些错误。

## 改动

两条确认路径最终都检查独立卡面信息：沿用已有可见区域掩码，再排除 32×32 描述图的第 20 列及其右侧（右侧 37.5%，覆盖单层与堆叠角标）。剩余像素按 RGB 各通道计算空间极差，最大极差不超过 `1/255` 时返回未知，并保留候选、分数、分差及 `flat_artwork` 拒绝原因。检查与角标边框检测、候选卡名和纯色具体颜色无关。

`1/255` 对应一个 8 位像素级别，目标是剔除纯色或量化级变化。普通与角标相似度门槛、可见区域、候选排序、出牌优先级、原检测模型均沿用原实现。低对比度真实卡面仍需扩大实机覆盖，不能把该规则理解为通用异常输入检测器。
