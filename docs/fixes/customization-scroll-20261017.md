# 自定义进入菜单后返回商店

现场 `debug/custom/2026-10-17.log` 在 02:55:40 记录“自定义暂缓原因：牌库翻页重叠未确认”。框架日志显示 02:55:39 已读出「輝くキミへ+」、剩余 1 次、100/40 的两个费用；没有执行购买。菜单返回列表属于先扫描进度的流程，随后牌库拼接失败才退出商店自定义阶段。

自定义扫描仍使用 290px/400ms 的 `post_swipe`，没有终点停留。快速拖动立即松手会让游戏滚动惯性继续移动，固定距离不能保证下一页仍包含上一页末行。严格的牌库拼接因此拒绝规划交易。此前删换牌的滑动修复没有覆盖这个入口。

改为复用 `deck_scroll_distance`，根据当前完整行计算距离，最多两行，保留一整行；通过 MaaFramework 原生 `Swipe` 使用 900ms 拖动和 350ms 终点停留。向上定位和向下扫描统一使用此方式；停止或滑动失败不继续扫描。目标顺序、完整牌库核对、名称/选项/费用/扣款确认以及原商店策略不变。

验证包含现场菜单 OCR 回放、用户截图的实际 MaaFramework 5.13.0 识别、完整与半页的重叠行检查、跨页目标规划、防重复规划及滑动失败检查。实际 5.13.0 Context 配合内存控制器验证原生拖动执行和松手前停留，不连接游戏。全量 796 项测试和 339 个子测试通过；尚未验证真实游戏滚动与自定义消费。
