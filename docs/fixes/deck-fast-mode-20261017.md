# 持牌检查与换牌快速模式

## 原因

2026-10-17 日志显示，04:31:46 至 04:32:34 的 16 次持牌检查滑动全部在回顶，未进入向下扫描。旧手势位于内容右边缘 x=690；页面停止判断又把检测框裁出的卡图缩放后直接比较，边框轻微抖动会导致无法确认停稳。现场没有保存对应游戏帧，因此不能仅凭日志确认每次手势具体落在了哪种控件上。

同次换牌虽然记录“快速命中”，但只要存在任何限一规则，就禁用了早停：第二页已找到候选，仍扫描第三页再返回。该条件把无关的限一规则变成了全库扫描要求。

## 修改

- 持牌检查改在卡牌内容内滑动，保留重叠行。使用固定尺寸卡图采样，允许小幅平移，识别静止页面；发现重复回顶循环时退出本次检查。
- 当前页面已经确认持有目标限一卡，立即返回。只有完整覆盖牌组且名称均确认后，才报告未持有；检查失败仍视为未知，关闭牌库并确认返回原页面。
- 培育设置在“使用体力药”前增加“快速命中模式”，默认开启。开启后，遇到可选的 N、黑名单牌或未受保护的 R，即可停止扫描并最终核名；无关限一规则不再阻止命中。关闭后比较牌组候选优先级。
- 白名单、限一卡最后一张、自定义稀有度和置灰状态继续参与原有资格判断。显式换出名单的已有覆盖关系不变。
- 删牌固定使用精确比较。若已证实全局最高候选，则允许提前结束比较；不要求为扫描而扫描。

## 验证

- Python 全量：882 项测试、339 项子测试通过。
- 原生设置：34 项检查通过，包含四种语言、开关顺序、保存重载及流水线参数。
- 回归覆盖已有牌立即返回、全量扫描才判定零张、重复回顶中止、限一卡和白名单保护、暗牌排除，以及快速与精确策略分离。
- 资源检查仍有 44 条既有诊断，无新增。
- 使用已有真实牌库截图做抖动采样回归，并保存现场手势记录；本轮没有控制游戏，实际滑动和长跑效果待现场验证。
