# 剧情确认与关注取消分离

## 问题与原因

另一台电脑 v2.0.1 的日志显示，关闭“启用关注租借”后，`ProduceFollow` 被覆盖为全屏匹配 `produce/cancel.png`。结算入口又先检查这个节点，再检查剧情确认。因此剧情跳过弹窗上的“取消”被当成“不关注”，导致跳过、取消反复执行。

2026-10-15 03:07:00.615 至 12:32:32.265，按动作 ID 去重，有 12,811 次关注分支的取消点击、12,810 次跳过点击，剧情确认动作 0 次。03:21:34.503 的日志已读出“早送り確認”“未読のコミュです”“早送りしますか?”，分数分别为 0.999896、0.999394、0.989951。这次故障是跨场景按钮误用与分支抢先，不是确认文字置信度过低。

## 本次修改

- 结算入口先处理剧情确认，再处理关注。
- 关注节点始终识别右侧“フォローする”按钮并核对文字；开关只决定在已识别的关注界面中选择关注或同行左侧的取消。不再将“关闭关注”转换成全屏取消模板。
- 剧情确认保留原模板及 0.9 门槛；增加标题和下方询问文字的 OCR 识别。仅有标题时先占住当前弹窗，不贸然确认。OCR 分支采用 0.8，不改变其他识别门槛。新按钮模板显式使用旧框架默认的 0.7。
- 点击前重新截图，重新确认当前弹窗，并在当前帧找按钮。剧情肯定按钮限在弹窗内容下方的右侧；不使用上次识别框或固定点击坐标。
- 按钮暂时缺失时，每次处理最多重读三帧；每轮最多点击一次，随后至少等待 700 毫秒，再由原入口重识别。场景变化则放弃旧操作。这里不新增结束培育、杀游戏或关闭助手的分支。
- 日文、汉化任务共用同一“启用关注租借”选项，保存的 Yes/No 含义与默认值保持一致。出牌、卡牌规则、饮料、商店、回忆策略没有因本次修复变更。
