# 培育列表滑动统一与简洁出牌耗时

`custom/scroll.py` 集中维护列表输入：900ms 拖动、终点按住 350ms 后松开。调用前及结束后检查停止状态，动作失败交回各场景已有的恢复流程，不据此确认翻页成功。每个入口仍负责自己的页面识别、距离、稳定帧和列表到底判断。

| 入口 | 保留的场景差异 |
| --- | --- |
| 咨询删牌、HIF 换出 | 按当前卡行计算步长；普通完整页最多三行，限一计数保留重叠 |
| HIF 自定义 | 按当前卡行计算步长，最多两行，保留完整重叠行 |
| 限一卡检查持有牌组 | 使用持有牌抽屉的 153px 行距和独立区域，最多两行；半页按最后完整行缩短距离 |
| 饮料保留列表 | 保留原列表坐标、480/500px 步长、滚动条定位和连续稳定帧确认 |
| 结算回忆读取 | 保留 310px 短滑和各页面内容区域，覆盖获得卡、卡组、钻石词条扫描及回顶 |

持有牌组改用较小步长后，回顶与扫描分别最多 16 次，以覆盖读取器支持的最多 120 张；75 秒总预算不变。没有取消重复计数、页间重叠或未知不能当不存在的检查。

回忆采用新手势有助于避免惯性越过词条，但不套用牌库“12 张”的距离。保留标题可见时原地重识别、内容位置判断到底、候选切换作废观察等原策略；读取失败仍交回结算入口。

特殊滑动保留：`ProduceLastPage/ProduceNextPage` 为剧本横向翻页；`SupportCardsNextPage` 已有 600ms 终点停留；培育外的工作选择、社团、商城手势不在本次范围。商店回血金额仍按原方式选档，不改成列表拖动。

出牌原本已经输出“出牌点击已观察 耗时:...秒”，简洁过滤器把耗时删掉。本次仅对该条完整格式放行，显示“出牌点击已观察（耗时 2.55 秒）”。沿用原出牌阶段计时，不把点击未确认误报成成功；其他识别参数继续隐藏，详细文件日志和看门狗原始日志不变。

验证：813 项测试及 339 个子测试通过；覆盖各区域与方向、半页保留行、停止/输入失败、简洁与详细控制台输出。真实 MaaFramework 5.13.0 配合内存控制器检查各入口的拖动与终点停留，无游戏输入。尚未完成真实游戏的回忆结算或新一轮培育长跑。
