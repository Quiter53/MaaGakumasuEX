# 回忆完成后奖励弹窗卡住

## 现场与原因

2026-10-17 debug 中，20:08:25 请求再生成，20:08:54 与 20:09:13 分别检查原候选与新候选，20:09:21 返回选定回忆结果页。20:09:32.873 起，OCR 正确读到「あさり先生シール獲得」（0.981513）。20:09:30 至 20:26:40 的窗口内，回忆 OCR 被调用 728 次，却没有调用 CloseRoundButton。

前次修复让回忆处理在未知帧保持接管，但离开回忆的目的页清单只覆盖主页、完成页、关注和剧情，漏掉原结算流程处理的圆形关闭按钮。奖励弹窗遮住完成页后，回忆处理便反复等待，阻止外层关闭弹窗；最终触发任务循环检测。这是流程接管范围的回归，不是本次 OCR 模型读错标题。

另一问题是刷卡回忆模式确认候选后没有记录“已完成选择”，仍按尚可再生成处理返回结果页。实际该页已没有再生成按钮，触发了误导性的“本轮未使用票”警告。

## 修改

- 只有提交过回忆“下一步”、当前已不是回忆页面并识别到实际圆形关闭按钮时，交回原结算节点关闭贴纸/物品弹窗。未完成回忆和空帧仍不盲点，也不凭关闭按钮就认定已经保存。
- 记录候选确认提交与随后返回结果页的状态。确认后的回忆直接完成结算，不再找已消失的再生成入口；中断回调仍保留该状态。
- 对真正反复未找到再生成入口的情况，改为描述“继续且不再尝试用票”，不推断过去有没有用票。

卡牌排名、用票限额、已配置策略、循环检测以及通用关闭按钮阈值均未调整。

## 验证

新增贴纸/物品弹窗交接、未提交下一步不得交接、仍在回忆页不得交接、缺失关闭按钮不盲点、两种培育模式确认候选后结束、回调中断恢复等回归测试。

对用户上传的桌面截图裁出游戏客户区并归一为 720×1280，使用实际 MaaFramework 5.13.0 和原 CloseRoundButton 模板离线识别：分数 0.921918，高于原门槛 0.8。该结果验证上传截图中的关闭按钮可被原模板识别，不等于实机完成整轮培育。

修复在 pre 维护，正式版 main/Latest 不在本次修复中改动。
